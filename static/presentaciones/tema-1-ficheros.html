01 · Presentación de la UD1

De java.io a java.nio.file

GeneraciónPaqueteAño
Primerajava.io.File1996
Segundajava.nio.file2011 (Java 7)
Limitación de File

Booleanos en vez de excepciones

delete(), mkdir(), renameTo() devuelven false sin decir por qué. No distingue "no existe" de "sin permiso".

Path (ruta), Files (operaciones estáticas) y WatchService (vigilancia sin polling) resuelven las tres carencias.
02 · Path, Paths y Files

Path: una ruta, no un fichero

Path.java
Path ruta = Path.of("datos", "entrada", "registro.csv"); ruta.getFileName(); // registro.csv ruta.getParent(); // datos/entrada ruta.isAbsolute(); // false
  • ▸
    Sin coste de E/S hasta que se usa junto a Files.
  • ▸
    resolve() compone rutas, nunca concatenación manual con +.
  • ▸
    normalize() limpia los . y .. de una ruta.
02 · Path, Paths y Files

Comprobar y crear

Files.java
Files.exists(ruta); Files.isDirectory(ruta); // crea todos los niveles intermedios Files.createDirectories(directorio); // lanza FileAlreadyExistsException Files.createFile(fichero);
No es defensa contra carreras

Files.exists() puede engañar

Devuelve false tanto si no existe como si no hay permisos. Entre comprobar y actuar, el fichero puede cambiar. Prefiere capturar la excepción de la operación real.

02 · Path, Paths y Files

Leer y escribir texto

Files.java
Files.writeString(fichero, "línea\n", UTF_8); Files.writeString(fichero, "más\n", UTF_8, StandardOpenOption.APPEND); String c = Files.readString(fichero, UTF_8); List<String> l = Files.readAllLines(fichero);
Cuidado con el tamaño

Cargan el fichero entero

readString y readAllLines son cómodos para configuración, pero no valen sobre ficheros grandes: para eso están los flujos por bloques.

Copiar, mover y borrar

Files.move también sirve para renombrar: un renombrado es, en esencia, un movimiento dentro del mismo padre. Para un árbol completo con contenido hay que recorrerlo primero.
02 · Path, Paths y Files

Excepciones, no booleanos

try/catch
try { Files.createDirectories(directorio); Files.copy(origen, destino, StandardCopyOption.REPLACE_EXISTING); } catch (IOException e) { // decides: reintentar, propagar... }
  • ▸
    IOException y subclases obligan a decidir en el momento de escribir el código.
  • ▸
    Files.copy no crea directorios padre. No es su responsabilidad.
03 · Recorrido de árboles

DirectoryStream: un solo nivel

DirectoryStream.java
try (var entradas = Files.newDirectoryStream(directorio, "*.csv")) { for (Path e : entradas) { System.out.println(e.getFileName()); } }
  • ▸
    Implementa AutoCloseable. Siempre dentro de try-with-resources.
  • ▸
    Filtro glob directamente al abrir el stream.
  • ▸
    No baja a subdirectorios. Solo el contenido directo.
03 · Recorrido de árboles

Files.walk: todo el árbol

Files.walk
try (Stream<Path> rutas = Files.walk(raiz)) { rutas.filter(Files::isRegularFile) .filter(soloLogs::matches) .forEach(System.out::println); }
Recurso del sistema operativo

Cierra siempre el Stream

Files.walk mantiene abierto un descriptor de directorio mientras se consume. Sin try-with-resources se acumulan sin liberar.

03 · Recorrido de árboles

walkFileTree: control fino

Borrar un árbol completo: visitFile borra ficheros, postVisitDirectory borra el directorio ya vacío. Files.walk para solo lectura; walkFileTree cuando hay que actuar.
03 · Recorrido de árboles

Atributos y permisos POSIX

BasicFileAttributes
BasicFileAttributes attrs = Files.readAttributes(fichero, BasicFileAttributes.class); attrs.size(); attrs.lastModifiedTime(); attrs.isDirectory();
UnsupportedOperationException

POSIX no existe en Windows

Windows usa ACL, no rwx por propietario/grupo/otros. Comprueba antes con supportedFileAttributeViews() si el código debe ser portable.

04 · WatchService

Vigilar sin polling

registro
try (WatchService watcher = FileSystems.getDefault().newWatchService()) { directorio.register(watcher, ENTRY_CREATE, ENTRY_MODIFY, ENTRY_DELETE); }
EventoSe dispara cuando...
ENTRY_CREATEse crea una entrada nueva
ENTRY_MODIFYse modifica el contenido
ENTRY_DELETEse elimina una entrada
04 · WatchService

El bucle de espera

bucle
while (true) { WatchKey clave = watcher.take(); for (WatchEvent<?> ev : clave.pollEvents()) { // procesar ev.context() } boolean valida = clave.reset(); if (!valida) break; }
Falla en silencio

reset() es obligatorio

Si se olvida, la clave deja de recibir eventos nuevos aunque el bucle siga ejecutándose, sin lanzar ninguna excepción.

04 · WatchService

take() frente a poll()

watcher.take()

Bloquea indefinidamente hasta que hay eventos. Adecuado para un hilo dedicado en segundo plano.

watcher.poll(t, unidad)

Devuelve null si no hay eventos en ese tiempo. Útil si el hilo debe atender otras tareas.

En Spring: un componente Runnable en un hilo gestionado, o @PostConstruct/@PreDestroy para abrir y cerrar el WatchService junto al contexto.

05 · Acceso secuencial y aleatorio

RandomAccessFile

registros.dat
try (var raf = new RandomAccessFile( "registros.dat", "rw")) { long tam = 64; raf.seek(3 * tam); // registro 3 byte[] buffer = new byte[(int) tam]; raf.readFully(buffer); }
Corrompe si el tamaño no cuadra

Escribir sobrescribe, no desplaza

Solo funciona de forma práctica con registros de tamaño fijo, o con un índice aparte de desplazamientos.

05 · Acceso secuencial y aleatorio

SeekableByteChannel: la versión NIO.2

SeekableByteChannel
try (var canal = Files.newByteChannel( fichero, READ, WRITE)) { canal.position(3 * 64); ByteBuffer buf = ByteBuffer.allocate(64); canal.read(buf); }
Se integra mejor con el resto de java.nio y es la opción preferible en código nuevo. RandomAccessFile sigue siendo válida en código existente.

07 · Streaming de binarios

Cuando el fichero no cabe en memoria

Memoria completa

Coste proporcional al tamaño

Cada fichero procesado consume memoria igual a su tamaño completo.

Muchas peticiones

Se agota antes de saturar CPU

Si el servidor atiende muchas a la vez, la memoria es el primer límite.

OutOfMemoryError

Sin forma razonable de recuperarse

Si el fichero supera lo disponible en la JVM.

La solución: tratar el fichero como un flujo de bytes que se procesa por partes, descartando cada bloque antes de pasar al siguiente.
07 · Streaming de binarios

Copia por bloques

streaming
try (InputStream in = Files.newInputStream(o); OutputStream out = Files.newOutputStream(d)) { byte[] buffer = new byte[8192]; int leidos; while ((leidos = in.read(buffer)) != -1) { out.write(buffer, 0, leidos); } }
Coste constante

La memoria es siempre la del buffer

8 KB en el ejemplo, sin importar si el fichero pesa 1 MB o 10 GB. Un tamaño razonable: entre 4 KB y 64 KB.

07 · Streaming de binarios

Procesar mientras se transfiere

hash SHA-256
while ((leidos = in.read(buffer)) != -1) { out.write(buffer, 0, leidos); digest.update(buffer, 0, leidos); } // nunca hay copia completa en memoria
  • ▸
    FileChannel.transferTo delega la copia en el sistema operativo.
  • ▸
    No garantiza todo en una llamada: hay que repetir hasta completar.
07 · Streaming de binarios

MultipartFile en Spring

guardar()
try (InputStream in = fichero.getInputStream(); OutputStream out = Files.newOutputStream(destino)) { // copia por bloques, igual que siempre }
Exactamente el problema a evitar

getBytes() carga todo en memoria

Para ficheros de tamaño no acotado, usa siempre getInputStream() y un bucle de copia por bloques.
